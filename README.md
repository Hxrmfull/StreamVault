# StreamVault

Запись прямых эфиров и скачивание готовых записей и клипов с Twitch, Kick,
YouTube и VK Video Live.

Два движка — запись эфиров и скачивание готового — и окно в стиле
стриминговой площадки поверх них. Всё, что умеет окно, доступно и из
командной строки.

Готовая программа для Windows — архив `StreamVault-<версия>-windows.zip`
в [выпусках](https://github.com/Hxrmfull/StreamVault/releases): распаковать
и запустить `StreamVault.exe` (см. «Готовая программа (exe)»).

## Что уже работает

Запись эфиров:

- Отслеживание каналов: Twitch опрашивается через Helix API раз в 15 секунд,
  остальные платформы — через streamlink. Окно показывает, кто в эфире,
  с кадром из трансляции.
- Запись по кнопке «Начать запись» / «Остановить запись» — и у канала
  из списка, и у любого другого — или автозапись каждого эфира (у нового
  канала выключена). Остановленная кнопкой запись не начинается снова сама,
  пока не кончится эфир; выключение автозаписи идущую запись не прерывает.
- Чат эфира всех четырёх площадок пишется рядом с записью (см. «Чат прямых
  эфиров»).
- Запись, начатая посреди эфира, берёт его с начала — насколько площадка
  хранит эфир назад (см. «Записи и диск»).
- Защита от переполнения диска и срок хранения записей (см. «Записи и диск»).
- Продолжение записи новой частью после обрыва, конвертация `.ts` → `.mp4`
  без перекодирования, повторы при сбоях ffmpeg, подбор записей прошлых запусков.
  Конвертацию можно выключить — запись останется в `.ts` (см. «Записи и диск»).
- Служба записи `LiveService` с управлением на ходу: добавить и убрать канал,
  начать и остановить запись, включить и выключить автозапись, сменить
  качество, проверить канал сразу.
- Автозапись у каждого канала выключена, пока её не включат; рядом с ней —
  «Настройки записи» канала поверх общих: качество, чат, запись с начала
  эфира, конвертация в mp4, подготовка mp4 к просмотру по сети, деление на
  куски, срок хранения (см. «Свои настройки канала»).
- Проверка записи на пропуски — куски эфира, которых нет в файле
  (см. «Пропуски в записи»).

Скачивание готового (через yt-dlp):

- Записи эфиров, хайлайты и клипы Twitch, записи и клипы Kick, видео
  и трансляции YouTube, записи и клипы VK Video Live — по ссылке. Клипы VK
  yt-dlp сам не знает — их понимает расширение программы
  (`streamvault/ytdlp_plugins`, подключается ключом `--plugin-dirs`).
- Списки записей и клипов канала на всех четырёх площадках (записи VK Video
  Live — открытым запросом сайта: yt-dlp их списка не знает), выбор качества,
  скачивание только отрезка. «Скачать всё» — вся вкладка канала разом;
  повторное нажатие докачивает только новое (сверка по id видео с очередью
  загрузок и файлами в папке загрузок).
- Очередь `DownloadManager`: несколько загрузок сразу, прогресс, пауза,
  отмена с уборкой недокачанного. Прерванное продолжается с того же места,
  в том числе после перезапуска программы.
- Чат записей и клипов Twitch, Kick и VK Video Live, прошедших эфиров
  YouTube:
  для браузера (HTML), полный JSON и по желанию видео чата (см. «Чат записей»).

Окно программы:

- Слева — отслеживаемые каналы с аватарками всех площадок (у Twitch —
  с ключами и без них): кто в эфире, сколько зрителей. Аватарка находится
  и у канала, открытого по ссылке, а не только из поиска.
- «Эфиры» — идущие трансляции с превью и счётчиком записи, остальные каналы
  с причиной, если что-то не так (канала нет, нет связи, не пишется).
- Страница канала — «Отслеживать», «Начать запись» / «Остановить запись»,
  «Автозапись» и рядом «Настройки записи», «Проверить»; вкладки
  с записями эфиров, хайлайтами и клипами, выбор нескольких для скачивания
  и «Скачать всё».
- Строка сверху — поиск каналов по имени сразу на Twitch, Kick, YouTube
  и VK Video Live (с аватарками, подписчиками и тем, кто в эфире) или ссылка
  на запись, клип, канал. Та же выдача — в окне «Добавить канал».
- «Загрузки» — прогресс, пауза, отмена, открыть файл или папку.
- «Библиотека» — всё записанное и скачанное с кадрами-превью и длительностью,
  поиск, отбор по каналу, площадке, типу (эфир, запись, клип, видео) и «есть
  чат», порядок по дате, длительности или размеру, удаление в корзину
  Windows; запись, оставленная в `.ts`, переводится в mp4 кнопкой на
  карточке. Части одного эфира (после обрывов) — одной карточкой с числом
  частей и общей длительностью. «Место на диске» — сколько занимают записи
  всего и по каналам и сколько свободно. Запись можно смотреть прямо
  в окне — чат идёт рядом в такт видео (см. «Просмотр с чатом»), а из неё —
  вырезать клип и наложить видео чата поверх (см. «Клип и видео с чатом»).
  «Сводка эфира» и «Поиск по чатам» всех записей — см. «Сводка и поиск
  по чатам».
- «Журнал» и настройки.

Работа в фоне: крестик сворачивает окно в трей, записи и загрузки идут
дальше. Значок в трее показывает, что пишется (с красной точкой во время
записи), в его меню — открыть окно, проверить каналы, папки и выход.
Пока окно свёрнуто, приходят уведомления о начале записи и о скачанном.
По желанию — запуск вместе с Windows сразу в трей.

Языки: русский и английский. При первом запуске берётся язык Windows
(всё, что не русское, — английский), дальше он меняется в настройках.
Переводятся окно, сообщения об ошибках, журнал и значок в трее;
консольные команды остаются на русском.

ffmpeg программа находит сама или берёт по пути, указанному вручную,
а если его нет — скачивает кнопкой из окна (подробнее — ниже).

## Что умеет каждая площадка

Особенности каждой площадки — в своём модуле `streamvault/sites/`. Чего
площадка не умеет, записано там с причиной; тест `tests/test_sites.py`
сверяет с реестром и эту таблицу.

| возможность | Twitch | Kick | YouTube | VK Video Live |
|---|---|---|---|---|
| поиск каналов по имени | да, по части имени | да, по части имени | да, через yt-dlp | да, только точное имя (см. «Поиск каналов») |
| имя и аватарка канала | да, Helix или GQL сайта | да | да, через yt-dlp | да |
| кадр идущего эфира | да | да | да | да |
| чат эфира | да | да | да, через yt-dlp | да |
| запись с начала эфира | да, сразу — из записи идущего эфира (если у канала включён архив) | да, сразу — из записи идущего эфира | да, после конца эфира — из опубликованной записи | да, после конца эфира — из записи канала |
| вкладки страницы канала | да: записи эфиров, хайлайты, загруженное, клипы | да: записи, клипы | да: трансляции, видео, Shorts | да: записи, клипы |
| клипы канала | да | да | нет — у YouTube нет списка клипов канала, вместо них вкладка Shorts | да |
| чат записей и клипов | да | да | да, у прошедших эфиров | да |

## Готовая программа (exe)

Папка `StreamVault` из сборки работает без установленного Python:

- `StreamVault.exe` — окно программы;
- `StreamVaultCLI.exe` — те же консольные команды, что `python -m streamvault`
  (`record`, `download`, `info`…), например `StreamVaultCLI.exe download ССЫЛКА`;
- `_internal` — библиотеки, streamlink и yt-dlp внутри; yt-dlp
  обновляется кнопкой из окна без пересборки (см. «Обновление yt-dlp»).

Программа переносная: настройки, журналы и свой ffmpeg хранит в своей
папке. Если туда писать нельзя (например, папку положили в
`Program Files`), — в `%APPDATA%\StreamVault`. ffmpeg в сборку не входит:
найдётся установленный или скачается кнопкой из окна.

Файлы не подписаны цифровой подписью, поэтому при первом запуске Windows
SmartScreen может предупредить «Система Windows защитила ваш компьютер»:
«Подробнее» → «Выполнить в любом случае».

### Обновления

Как в DTTConvert: при запуске (если не отключено в настройках)
и по кнопке «Проверить обновления» программа спрашивает у GitHub последний
выпуск. Есть новее — сверху появляется кнопка «Обновление X»: «Скачать
и установить», затем «Перезапустить и обновить».

- Архив выпуска обязан совпасть по размеру и сумме sha256 с тем, что
  сообщает GitHub (он считает сумму сам, когда файл выкладывают).
  Не сошлось — ничего не ставится.
- Внутри архива — только файлы программы; что-то лишнее — отказ.
- Запущенную программу не заменить, поэтому новая версия распаковывается
  в `update\`, программа закрывается, а `StreamVaultCLI.exe` новой версии
  ждёт её выхода, меняет `StreamVault.exe`, `StreamVaultCLI.exe` и
  `_internal` и запускает обновлённую. Не вышло — старое возвращается
  на место, программа запускается прежней и говорит, что не так.
- Настройки и список каналов (`settings.json`), очередь загрузок, журналы
  и скачанные кнопками ffmpeg, yt-dlp и TwitchDownloader не трогаются.

Запущенная из исходников программа только сообщает о новой версии:
её обновляют через `git pull`.

### Выпуск новой версии

```
python packaging\release.py 0.2.0
```

Версия должна совпадать с `streamvault/__init__.py`. Скрипт собирает
программу и публикует выпуск `v0.2.0` с архивом через `gh`.
`--notes файл.md` — описание выпуска, `--dry-run` — только собрать.

### Сборка

```
python packaging\build.py
```

Сборка идёт в отдельном окружении `build\venv` (создаётся при первом
запуске, ставит только `requirements.txt` и PyInstaller), результат —
`dist\StreamVault` и архив `dist\StreamVault-<версия>-windows.zip`.

Программой можно пользоваться прямо из `dist\StreamVault`: новая сборка
меняет там только `StreamVault.exe`, `StreamVaultCLI.exe` и `_internal`,
а настройки, очередь загрузок, журналы и скачанные кнопками ffmpeg,
yt-dlp и TwitchDownloader остаются. Запущенную программу не обновить —
сборка попросит её закрыть и ничего не тронет.

## Установка из исходников

Нужны Python 3.12+ и [streamlink](https://streamlink.github.io/).
[ffmpeg](https://ffmpeg.org/) ставить заранее не обязательно — см. ниже.

```
python -m pip install -r requirements.txt
```

## Записи и диск

Запись эфира проходит через диск несколько раз: streamlink пишет `.ts`,
ffmpeg переписывает его в `.mp4` и, чтобы видео сразу играло по сети,
ещё раз переносит оглавление mp4 в начало файла. Обе перезаписи
отключаются в настройках, раздел «Запись эфиров»:

- «Конвертировать записи в mp4» — выключено: запись остаётся в `.ts`
  и пишется на диск один раз. `.ts` открывают VLC, MPC и mpv; в mp4 её
  можно перевести потом кнопкой «Конвертировать в mp4» на карточке
  в библиотеке — mp4 ляжет рядом, `.ts` удалится, чат останется при записи.
- «Готовить mp4 к просмотру по сети» — выключено: mp4 пишется на одну
  перезапись меньше. На компьютере он играет как обычно, а по сети
  (браузер, мессенджер, облако, домашний сервер) его сначала придётся
  скачать целиком.

### Деление записи на куски

«Делить запись на куски» (раздел «Запись эфиров») — при конвертации в mp4,
без перекодирования, так же быстро, как обычная конвертация:

- **по размеру** — куски не больше заданного (ГБ). Запись делится на
  равные куски, а не «по 2 ГБ и остаток»: 4,1 ГБ при 2 ГБ — три куска
  по 1,4 ГБ, а не 2 + 2 + 0,1;
- **по длительности** — по столько-то минут; хвост короче минуты
  прилипает к последнему куску;
- **на равные части** — на сколько частей делить.

Режет ffmpeg по ключевым кадрам, поэтому куски выходят примерно такими,
а не точно до байта и секунды. Имена — `… - piece 1 of 3.mp4`; в библиотеке
куски — одной карточкой эфира и смотрятся подряд. Чат делится вместе
с записью: у каждого куска свой `.chat.json` со временем от его начала.
Части эфира после обрывов (`part02` и дальше) делятся каждая отдельно.
Короче двух минут запись не делится. Запись, оставленная в `.ts`
(конвертация выключена), делится, когда её переводят в mp4 кнопкой.

### С начала эфира

Поток эфира, который пишет streamlink, держит лишь последние 15–25 секунд —
раньше там ничего нет. Начало эфира есть в его записи на самой площадке: так
перематывают и их сайты. Поэтому, если запись началась, когда эфир уже шёл
(программу запустили позже, нажали «Начать запись» посреди эфира), запись
идёт как обычно, а кусок от начала эфира до начала записи (и 15 секунд
сверху, чтобы между частями не было дыры) скачивается из записи эфира
очередью загрузок — с прогрессом в «Загрузках» и чатом этого куска — и
ложится рядом первой частью «… - part00». В библиотеке части эфира — одной
карточкой и играют подряд.

- Twitch — сразу: запись эфира пишется с первой секунды (`archiveVideo`
  из GQL сайта). Её нет, если у канала выключен архив прошедших эфиров —
  тогда начала нет нигде, и программа так и пишет.
- Kick — сразу: идущий эфир лежит в записях канала (`is_live`).
- YouTube — после конца эфира: перемотку трансляции yt-dlp кусками не
  скачивает, а опубликованное видео — да. Нет записи у трансляции (YouTube
  не сохраняет эфиры без перемотки и длиннее 12 часов) — начала не взять.
- VK Video Live — после конца эфира: из записей канала.

Что с началом, видно на странице канала под записью: ищется, скачается
после конца эфира, скачивается, или почему его не взять. Начало добирается
окном программы (через его очередь загрузок): консольная запись (`record`)
пишет с текущего места. Если программу закрыли до конца эфира YouTube или
VK, начало этого эфира не скачается — его можно скачать потом со страницы
канала отрезком.

Включается в настройках («Записывать с начала эфира, если запись началась
позже») и у канала — в «Настройках записи»; по умолчанию выключено: начало
многочасового эфира — это гигабайты.

### Место на диске

Перед каждой частью записи и раз в минуту во время неё программа смотрит,
сколько свободно на диске с записями. Меньше порога («Оставлять свободным
на диске», по умолчанию 5 ГБ) — предупреждение в журнале, плашка в окне
и уведомление в трее. Меньше пятой части порога — запись останавливается:
лучше остановить её, чем получить битый файл. Записанное уходит в обработку
как обычно, а запись продолжится сама, когда место освободят. 0 — не следить.

### Свои настройки канала

Автозапись у канала выключена, пока её не включат переключателем
«Автозапись» на его странице: так и у добавленного из окна, и у канала,
вписанного в `settings.json` без `"enabled": true`. Каналы консольной
записи (`record -u`) и перенесённые из старого StreamRecorder пишутся —
для этого их и указали.

Рядом с переключателем — «Настройки записи»: всё, что относится к записи
этого канала, в одном окне — качество, чат прямых эфиров, запись с начала
эфира, конвертация в mp4, подготовка mp4 к просмотру по сети, деление на
куски (способ и число) и срок хранения записей. Что не выбрано — как в общих
настройках («как в настройках: да» показывает, что выйдет). Хранятся в
`settings.json` у канала: `"quality"`, `"keep_days"` и
`"options": {"split_mode": "size", "split_size_gb": 3.5}`. Идущая запись
подхватывает изменения со следующей части, конвертация — со следующей записи.

### Пропуски в записи

Когда streamlink не успевает за площадкой (сеть, перегруженный диск) или
выбрасывает рекламу Twitch, в записи нет куска эфира: время кадров прыгает
вперёд. Перед конвертацией программа проходит `.ts` ffmpeg'ом без
декодирования (`-c copy -f framecrc`, один быстрый проход по файлу) и
запоминает такие места в `cache\integrity.json`:

- на карточке в библиотеке — «2 пропуска» (в подсказке — сколько пропало);
- на шкале проигрывателя — пометки: полоса, если видео на пропуске
  замирает, черта, если пропуск склеен;
- в «Сводке эфира» — список по частям, щелчок — к этому месту.

Проверять надо именно `.ts`: конвертация в mp4 сама склеивает прыжки
дольше 10 секунд (так ffmpeg обходится с обрывами mpegts), и в mp4 такой
пропуск уже не виден. Заодно проверка знает настоящую длительность
видео со склеенными пропусками — по ней делится запись на куски и идёт
шкала проигрывателя у записи, оставленной в `.ts`. Записи, сделанные
раньше, и скачанное проверяются кнопкой «Проверить» в сводке (у mp4 видны
только пропуски, оставшиеся во времени видео). Пропуск между частями эфира
(обрыв и новая часть) — это сами части, отдельно не помечается.

### Срок хранения

«Хранить записи, дней» — записи эфиров старше срока раз в час уходят
в корзину Windows вместе с чатом, как кнопкой «Удалить» в библиотеке; что
удалено — в журнале. Срок бывает и свой у канала (выбор на странице канала).
Возраст записи — по дате в имени файла. 0 — хранить всегда (по умолчанию).
Скачанные записи и клипы срок не трогает.

## ffmpeg

ffmpeg нужен, чтобы конвертировать записи эфиров в mp4, склеивать видео
и звук YouTube и вырезать отрезки. Программа ищет его сама — в таком порядке:

1. путь, указанный вручную в настройках («Указать путь к ffmpeg вручную»,
   с выбором файла и проверкой, что это действительно ffmpeg);
2. своя копия в `tools\ffmpeg` рядом с программой;
3. PATH;
4. обычные места установки: winget, scoop, chocolatey, `C:\ffmpeg`,
   `Program Files\ffmpeg`.

Если ffmpeg нет нигде, окно показывает плашку с кнопкой «Скачать ffmpeg».
Записи эфиров тем временем ждут в `.ts` и сконвертируются сами, когда
ffmpeg появится.

Кнопка скачивает сборку [gyan.dev](https://www.gyan.dev/ffmpeg/builds/),
на которую ссылается ffmpeg.org, около 115 МБ. Один и тот же архив лежит
в двух местах, и программа переходит между ними сама:

1. GitHub (GyanD/codexffmpeg) — основной источник;
2. сам gyan.dev — если GitHub недоступен, обрывает связь (после двух
   попыток) или отдаёт медленнее 256 КБ/с за 20 секунд;
3. снова GitHub, но через `api.github.com` — другой адрес входа к тому же
   файлу, на случай если режется именно `github.com`.

Загрузка продолжается с того же места, а не с нуля. Если не вышло нигде,
окно предлагает «Скачать вручную»: страница
сборок откроется в браузере, архив останется распаковать и указать путь
к `bin\ffmpeg.exe` в настройках.

Чтобы подменённый файл не установился:

- контрольная сумма sha256 берётся в независимых местах — у GitHub,
  на gyan.dev и из списка, встроенного в программу; нужно хотя бы два
  совпадения и ни одного расхождения (так установка работает, даже когда
  один из сайтов недоступен);
- скачанный архив обязан дать ровно эту сумму и ровно этот размер;
- только https и только известные адреса; перенаправление проверяется
  до подключения, к чужому серверу программа не обращается;
- из архива берутся только `ffmpeg.exe` и `ffprobe.exe` по точному пути;
- установленный ffmpeg должен запуститься и назвать ту же версию.

ffmpeg ложится в `tools\ffmpeg` рядом с программой; в системе ничего
не меняется, PATH не трогается.

## Первый запуск

Скопировать `settings.example.json` в `settings.json` и заполнить — или
добавить каналы из окна. Настройки старого консольного рекордера
StreamRecorder переносятся командой:

```
python -m streamvault import-config ПУТЬ\config.py
```

## Поиск каналов

Имя канала набирается в строке сверху как есть — без `kick:` и ссылок.
Под строкой появляется выдача каждой платформы:

- Twitch — поиск по части имени, как на twitch.tv: аватарки, подписчики,
  кто в эфире и сколько зрителей;
- Kick — поиск kick.com (аватарок в его выдаче нет — они подтягиваются
  открытыми сведениями о канале, когда его открывают);
- YouTube — каналы со страницы поиска YouTube через yt-dlp (пара секунд);
- VK Video Live — проверяется точное имя канала. Открытого запроса, которым
  сайт ищет по части имени без входа, пока не нашлось; если он есть,
  поиск станет таким же, как у остальных.

Ключи не нужны: программа спрашивает платформы так же, как их сайты.
Платформа не ответила — в её разделе написано почему, остальные работают.
Стрелки и Enter выбирают канал из выдачи, Enter без выбора открывает
введённое как раньше: ссылку, `kick:имя` или канал Twitch.

## Окно программы

Двойной щелчок по `StreamVault.pyw` — или в консоли:

```
python -m streamvault
```

Крестик окна сворачивает программу в трей — выйти можно из меню значка
в трее или кнопкой выхода справа вверху. При выходе записанное
конвертируется в mp4, недокачанное продолжится при следующем запуске.
Повторный запуск не открывает вторую копию, а разворачивает уже запущенную.

Запуск сразу в трей, без окна (так программу запускает Windows, если
включить это в настройках):

```
python -m streamvault gui --tray
```

То же окно в браузере — если отдельное окно почему-то не открывается:

```
python -m streamvault gui --browser
```

Запущенный StreamVault может быть только один: вторая копия записывала бы
те же каналы. Консольные `record` и `download` при открытом окне откажутся
работать.

### Просмотр с чатом

Запись смотрится прямо в окне программы — как на Twitch: видео на всё
окно, справа чат в такт видео (со смайлами, значками и цветами ников), под
видео — канал и название. Кнопка «Смотреть» — на карточке в библиотеке;
если рядом с записью лежит `.chat.json`, чат идёт вместе с ней.
«Открыть в проигрывателе» — та же запись в обычном проигрывателе.

- Кнопки свои у любого видео: шкала на всю ширину (толще при наведении,
  время под курсором), пауза, громкость (ползунок при наведении), время;
  справа — шестерёнка со скоростью (0,5–2×), клип, режим кинотеатра (без
  полосы с названием) и во весь экран. Пока смотрят и мышь стоит, кнопки
  и курсор прячутся. Щелчок по видео — пауза, двойной — во весь экран.
- Клавиши: пробел — пауза, ←/→ — на 10 секунд, F — во весь экран,
  M — без звука, `[` и `]` — начало и конец клипа. Работают и у `.ts`.
- Чат: шапка «Чат» с кнопкой «свернуть» (видео на всю ширину, развернуть —
  кнопкой на видео); лупа — поиск по чату, щелчок по найденному — к этому
  месту записи; шестерёнка — размер шрифта, сдвиг чата (если спешит или
  отстаёт), время сообщений. Листаешь чат назад — он не убегает вниз,
  а внизу полоса «Чат приостановлен из-за прокрутки».
- Продолжить с места: где остановился просмотр, программа помнит сама
  (`cache\positions.json`) и при следующем открытии предлагает
  «Продолжить» или «С начала». Досмотренное (последние 2 %) открывается
  с начала.
- Эфир из нескольких частей (после обрывов) и куски поделённой записи
  идут подряд: под видео переключатель «часть N из M», следующая часть
  включается сама, когда кончилась текущая.
- Скорость, громкость, чат, его шрифт и кинотеатр окно помнит само.
- Кадры на шкале: наведёшь на шкалу — над ней кадр из этого места записи,
  как на Twitch. Их ffmpeg один раз собирает в листы по 10×10 маленьких
  кадров (`cache\storyboards`, не больше 100 последних записей),
  декодируя только ключевые кадры: многочасовой эфир — за минуту-две,
  пока смотришь. Кадр — не чаще раза в 2 секунды и не больше 500 на запись.
- График чата над шкалой: сколько сообщений в каждом отрезке записи
  (около 240 столбиков), точки — всплески чата, где писали заметно больше
  обычного. Щелчок по точке — к этому месту, за 15 секунд до всплеска:
  чат реагирует позже события. Выключается в шестерёнке («График чата»).
  У идущей записи график растёт вместе с ней.
- Пропуски в записи помечены на шкале (см. «Пропуски в записи»).

- Видео окну отдаёт маленький сервер программы: только на 127.0.0.1,
  со случайным токеном в адресе и только проверенные файлы записей
  и картинки открытого чата.
- Чат подгружается кусками по две минуты вокруг текущего места — и у
  многочасового эфира с сотнями тысяч сообщений окно открывается сразу.
- Запись в `.ts` браузерная часть окна сама не проигрывает — её на лету
  перепаковывает ffmpeg (без перекодирования, файл не меняется);
  перемотка запрашивает поток с нового места и занимает доли секунды.
  Без ffmpeg на месте видео — кнопки «Конвертировать в mp4» и «Открыть
  в проигрывателе».
- Запись эфира бывает оборвана на полукадре. Если видео споткнулось уже
  во время просмотра, окно открывает его заново чуть дальше этого места,
  а у самого конца ставит на паузу.
- Чтобы смайлы 7TV, BTTV и FFZ были видны и в окне, программа встраивает
  их в `.chat.json` чата эфира Twitch (см. «Чат прямых эфиров»). У чатов,
  записанных раньше, смайлы Twitch берутся с сайта Twitch, а 7TV, BTTV,
  FFZ и значки не видны.

### Смотреть идущую запись

Пока эфир пишется, у канала в «Эфирах» и на его странице есть кнопка
«Смотреть»: тот же проигрыватель с чатом, но запись ещё растёт.

- Открывается у края записи — на несколько секунд позади того, что уже
  записано. Шкала растёт вместе с записью; назад можно перематывать до её
  начала, «К эфиру» возвращает к краю. Клавиши и скорость — как обычно.
- Видео — записываемый `.ts`: ffmpeg перепаковывает его на лету и читает
  файл по мере роста (`-follow`). Нужен ffmpeg.
- Чат читается прямо из `.chat.jsonl`, который пишется рядом с записью,
  и догружается по ходу. Встроенных картинок у такой записи ещё нет:
  смайлы и значки Kick, VK и YouTube и смайлы Twitch идут адресами площадок,
  а значки Twitch и смайлы 7TV, BTTV и FFZ появятся, когда запись допишется.
- Эфир оборвался и пошёл новой частью — проигрыватель сам переходит к ней
  (если перемотали назад — когда досмотрят эту часть). Эфир кончился —
  об этом уведомление, а запись появится в библиотеке после обработки.
- Если запись взяла эфир с начала (`--hls-live-restart`), видео начинается
  раньше, чем пошёл чат. Программа сдвигает чат на эту разницу — и здесь,
  и в готовом `.chat.json` (по длине видео и меткам начала и конца части
  в `.chat.jsonl`).

### Сводка и поиск по чатам

- **Сводка эфира** — кнопка на карточке в библиотеке и «Сводка» под видео:
  по всем частям эфира длительность, размер, сколько сообщений и сколько
  зрителей писали, сообщений в минуту, горячие моменты (самые сильные
  всплески чата — щелчок открывает запись чуть раньше), самые активные
  в чате, частые смайлы и пропуски в записи с кнопкой «Проверить».
- **Поиск по чатам** — кнопка в библиотеке: слово, фразу или смайл во всех
  чатах библиотеки сразу, или ник («по нику»). Без учёта регистра, и
  кириллицы тоже. Найденное — по записям, щелчок по сообщению открывает
  запись на этом месте.
- Чаты для этого один раз переписываются в базу `cache\chats.sqlite`
  (ник, текст, названия смайлов — без картинок): первый поиск дольше,
  и, если чатов много, окно досматривает их порциями по несколько секунд,
  показывая уже найденное. Изменился или удалён `.chat.json` — база
  поправится сама при следующем поиске.

### Клип и видео с чатом

- **Клип.** В проигрывателе — «Клип»: «Начало» и «Конец» отмечают текущее
  место записи (или клавиши `[` и `]`), «Сохранить клип». ffmpeg режет
  без перекодирования, за секунды, но по ключевым кадрам: начало уходит
  к ближайшему ключевому кадру раньше отметки, обычно на пару секунд.
  С галочкой «с чатом» рядом ложится `.chat.json` этого отрезка со временем
  от начала клипа (выровненным по настоящему началу видео) — клип
  смотрится в окне с чатом, как запись.
- **Видео с чатом поверх.** На карточке записи, у которой есть видео чата
  (`.chat.mp4`, режим «чат + видео чата»), — кнопка «Видео с чатом поверх»:
  чат справа или слева, высотой с запись. Это перекодирование всего видео
  (libx264), поэтому долго; ход и отмена — в «Загрузках», раздел «Правка
  записей». Видео выходит длиной с запись: кончилось видео чата — дальше
  запись без него. У эфира из частей — каждая часть, у которой есть видео чата.
- Результат ложится рядом с записью, сама запись не меняется. В имени —
  метка `[clip 00h01m02s-00h02m00s]` или `[chat]`: по ней библиотека
  показывает клип и видео с чатом отдельными карточками, а не частями эфира,
  и «Скачать всё» не считает клип скачанным целым видео.

## Запись из консоли

```
python -m streamvault record
```

Либо двойным щелчком по `record.cmd`. Остановка — Ctrl+C: идущая запись
закрывается и конвертируется. Повторный Ctrl+C выходит сразу,
необработанное подхватится при следующем запуске.

Разовая запись канала без изменения настроек:

```
python -m streamvault record -u kick:xqc -q 720p60
```

Канал записывается как `kick:xqc`, `youtube:@handle`, ссылкой или просто
именем — тогда это Twitch.

## Скачивание записей и клипов

Что есть у канала — записи эфиров (по умолчанию), клипы, хайлайты:

```
python -m streamvault info twitch:xqc
python -m streamvault info twitch:xqc --kind clips --period 7d
python -m streamvault info kick:xqc --kind clips
python -m streamvault info youtube:LinusTechTips --limit 5
python -m streamvault info vkvideolive:iserveri
```

Что лежит по ссылке и в каком качестве её можно скачать:

```
python -m streamvault info https://www.twitch.tv/videos/2909822254
```

Скачать одну или несколько ссылок:

```
python -m streamvault download https://www.twitch.tv/videos/2909822254 -q 720
python -m streamvault download ССЫЛКА --section 1:00:00-1:30:00
python -m streamvault download ССЫЛКА --chat render
```

`-q` — `best`, `worst`, `audio`, высота кадра (`1080`, `720`...) или формат
из `info`. `--section` скачивает только отрезок. `--chat` — чат Twitch:
`none`, `text` или `render` (см. «Чат записей»). Файлы ложатся
в `downloads\<платформа>\<канал>\` внутри `root_path`. Ctrl+C останавливает
загрузку, не теряя скачанного: та же команда продолжит её с того же места.

Записи только для подписчиков скачиваются от имени твоего аккаунта Twitch.
Проще всего — токеном: в браузере на twitch.tv нажми F12 → Application →
Cookies → twitch.tv, скопируй значение `auth-token` и вставь в настройках
окна. Токен даёт полный доступ к аккаунту, как пароль: он хранится только
в `settings.json`, а yt-dlp получает его во временном файле, который сразу
удаляется. Другие способы — через `ytdlp_extra_args`: `--cookies файл.txt`
(выгруженный расширением браузера) или `--cookies-from-browser firefox`.

### Чат записей

Вместе с видео можно скачать и чат — у записей эфиров, хайлайтов и клипов
Twitch, записей и клипов Kick и VK Video Live, прошедших эфиров YouTube.
В окне скачивания
(и при выборе нескольких записей канала) есть выбор «Чат»:

- «без чата»;
- «чат» — рядом с видео ложатся `.chat.html` (читать в браузере, смайлы
  внутри) и `.chat.json` (полный чат: из него можно снова сделать HTML или
  видео чата, даже когда запись с Twitch удалят);
- «чат + видео чата» — ещё и `.chat.mp4`: чат отдельным видео, которое
  можно положить рядом с записью или поверх неё в монтаже. Нужен ffmpeg.

Если скачивается отрезок, чат — тоже только этого отрезка. Чат по умолчанию,
размер видео чата и шрифт задаются в настройках (раздел «Чат»). К уже
скачанной записи чат можно докачать кнопкой «Скачать чат» в загрузках —
видео заново не качается. Не скачался чат (например, запись удалили, и
у вырезанного из неё клипа чата уже нет) — видео всё равно готово, а причина
видна в загрузках. Остановка или отмена во время чата прерывает только чат.

Откуда берётся чат:

- Twitch — [TwitchDownloader](https://github.com/lay295/TwitchDownloader)
  скачивает его сам, со смайлами Twitch, 7TV, BTTV и FFZ.
- YouTube — yt-dlp скачивает чат прошедшего эфира целиком (у обычного видео
  чата нет — выбор «Чат» для него не показывается); время сообщений берётся
  из записи, так что чат идёт ровно с видео.
- Kick — история чата канала открыта: программа проходит её от конца записи
  к началу, по 25 сообщений за запрос, с паузами, чтобы не нагружать сайт.
  Длинная запись с оживлённым чатом скачивается несколько минут. Клип —
  кусок эфира: его начало и длительность Kick сообщает сам.
- VK Video Live — чат записи открыт, как на её странице: сообщения со временем
  в записи, по 200 за запрос, от начала к концу. Пятичасовая запись — около
  20 секунд. Чат клипа — чат его отрезка записи.

Смайлы и значки YouTube, Kick и VK Video Live программа скачивает и встраивает в `.chat.json`,
а HTML и видео чата из него делает TwitchDownloader — уже без обращения
к Twitch. Нет TwitchDownloader — чат остаётся в `.chat.json`: смотреть
с чатом в окне можно и так, а HTML сделается позже кнопкой «Скачать чат».

TwitchDownloader, как и ffmpeg, в программу не входит: он скачивается
кнопкой в настройках (около 50 МБ) — с GitHub, а если режется `github.com`,
через `api.github.com`. Сумма архива сверяется у GitHub, в каталоге scoop
и по списку, встроенному в программу: нужно хотя бы два совпадения и ни
одного расхождения. Если новейшую версию scoop ещё не знает, ставится та,
что сверяется в двух местах. Из архива берётся только `TwitchDownloaderCLI.exe`
с лицензиями, и он должен запуститься и назвать ту же версию. Уже
установленный (например, через scoop) находится в PATH.

### Чат прямых эфиров

Пока идёт запись эфира, программа читает чат канала — анонимно, как
зритель без входа, — и сохраняет его рядом с записью. После эфира рядом
с готовым видео ложатся те же файлы, что у чата записей: `.chat.json`
и `.chat.html`, а в режиме «чат + видео чата» — и `.chat.mp4`.

Как читается чат — так же, как его читает страница канала у зрителя:

- Twitch — IRC-чат под анонимным именем;
- Kick — websocket чата с гостевым подключением, которое выдаёт сам Kick;
- VK Video Live — последние сообщения раз в 3 секунды; если за паузу их
  больше, чем в ответе, берётся ответ подлиннее;
- YouTube — через yt-dlp: он читает чат идущего эфира, программа — его файл
  по мере роста.

Подробности:

- Сообщения пишутся на диск по мере прихода (`.chat.jsonl` рядом с `.ts`):
  программа упала или выключили компьютер — записанное не пропадает.
- Связь с чатом прервалась — программа переподключается сама; в журнал
  пишется первый обрыв, а не каждая попытка.
- Удалённые модераторами сообщения и сообщения забаненных в чат
  не попадают. Подписки и подарки Twitch, Super Chat и спонсорство YouTube —
  попадают, с текстом площадки.
- Смайлы Twitch, 7TV, BTTV и FFZ и значки Twitch TwitchDownloader
  встраивает в `.chat.json` сразу после эфира: так HTML и видео чата
  делаются без сети, а в проигрывателе окна видны все смайлы. Не вышло
  (нет сети) — HTML скачает их сам, как раньше. Смайлы и значки Kick,
  VK Video Live и YouTube он не знает — программа скачивает их картинки
  и встраивает в `.chat.json`, а цвета ников берёт у площадки.
- Нет TwitchDownloader — чат ждёт в `.chat.json`, HTML сделается, как
  только его скачают кнопкой. Программу закрыли, пока рисовалось видео
  чата, — недорисованный файл удаляется, а видео доделывается при
  следующем запуске.
- Время сообщений — от начала части записи. Видео эфира отстаёт от чата
  на несколько секунд, как у любого зрителя трансляции.

Включается в настройках, раздел «Чат»: «Чат прямых эфиров при записи»
(по умолчанию — «чат»).

### Обновление yt-dlp

yt-dlp часто обновляется вслед за сайтами: когда сайт меняется, старая
версия перестаёт его понимать. Обновить можно кнопкой «Обновить yt-dlp»
в настройках — она же появляется на странице загрузок, когда что-то
не скачалось. Пересобирать программу для этого не нужно.

Источники, по порядку:

1. GitHub, выпуск yt-dlp/yt-dlp — сборка `yt-dlp` (zip с кодом, 3 МБ;
   внутри и скрипты yt-dlp-ejs для YouTube своей версии);
2. PyPI — wheel той же версии, если GitHub недоступен или медленнее
   64 КБ/с;
3. снова GitHub, но через `api.github.com` — на случай, если закрыт именно
   `github.com`; так же берутся и список сумм с подписью.

Как проверяется, что ничего не подменили:

- у каждого выпуска yt-dlp есть список сумм `SHA2-256SUMS`, подписанный
  ключом разработчиков. Подпись проверяется ключом, встроенным в программу
  (отпечаток `AC0C BBE6 848D 6A87 3464 AF4E 57CF 6593 3B5A 7581`, тот же
  ключ — в их репозитории и на keys.openpgp.org). Сумма, которую посчитал
  сам GitHub, обязана совпасть с подписанной;
- подпись не сошлась или суммы разошлись — обновление останавливается
  совсем, без перехода на PyPI: это признак подмены, а не плохой связи;
- wheel с PyPI сверяется с суммой, которую публикует PyPI (так проверяет
  и pip);
- скачанный файл обязан дать ровно эту сумму, внутри — ровно эта версия;
- обновлённый yt-dlp должен запуститься и назвать ту же версию.

Обновление ложится в `tools\yt-dlp` рядом с программой, рядом со старым:
уже идущие загрузки доделываются прежней версией. Запускается та копия,
что новее, — встроенная в программу (или установленная через pip) либо
обновлённая; после пересборки со свежим yt-dlp старое обновление просто
перестаёт использоваться.

Из исходников yt-dlp можно обновлять и как обычно:

```
python -m pip install -U yt-dlp
```

| `root_path` | куда складывать записи: внутри появятся `in-progress\<платформа>\<канал>` (пишется или ждёт конвертации) и `finished\<платформа>\<канал>` (готовые). Папки прошлых версий `recorded` и `processed` переименовываются сами |
| `quality` | качество по умолчанию: `best`, `1080p60`, `720p`, `worst` |

| `twitch_client_id`, `twitch_client_secret` | приложение с [dev.twitch.tv](https://dev.twitch.tv/console/apps) для опроса Twitch раз в 15 с; без него Twitch опрашивается через streamlink (как получить — см. «Ключи Twitch») |
| `refresh` | интервал опроса по платформам, секунды; не меньше 15 для Twitch и 30 для остальных |

| `ffmpeg_path` | путь к ffmpeg; пусто — найти самой (см. «ffmpeg») |
| `convert_recordings` | конвертировать записи эфиров в mp4; `false` — оставлять `.ts` (см. «Записи и диск») |
| `mp4_faststart` | готовить mp4 к просмотру по сети (оглавление в начале файла, ещё одна перезапись) |
| `split_mode`, `split_size_gb`, `split_minutes`, `split_count` | делить запись на куски при конвертации: `off`, `size` (куски не больше `split_size_gb` ГБ), `duration` (по `split_minutes` минут), `count` (на `split_count` частей) — см. «Деление записи на куски» |
| `record_from_start` | запись, начатая посреди эфира, добирает его начало из записи эфира на площадке; по умолчанию выключено (см. «С начала эфира») |
| `min_free_gb` | сколько гигабайт оставлять свободными на диске с записями; 0 — не следить (см. «Место на диске») |
| `keep_days` | сколько дней хранить записи эфиров; 0 — всегда. У канала — свой `keep_days` (см. «Срок хранения») |
| `ffmpeg_attempts`, `ffmpeg_retry_delay` | повторы конвертации после сбоя ffmpeg |
| `drain_grace` | сколько после остановки доделывать очередь конвертации |
| `downloads_path` | куда скачивать записи и клипы; пусто — `downloads` внутри `root_path` |
| `download_quality` | качество скачивания по умолчанию |
| `max_downloads` | сколько загрузок идёт одновременно |
| `download_fragments` | сколько кусков записи качать параллельно |
| `twitch_auth_token` | кука `auth-token` для записей только для подписчиков |
| `ytdlp_extra_args` | дополнительные аргументы yt-dlp; полезные — в подсказке «?» в настройках |
| `chat_mode` | чат Twitch по умолчанию: `none`, `text` (HTML и JSON) или `render` (ещё и видео чата) |
| `live_chat` | чат прямых эфиров Twitch при записи: `none`, `text` или `render` |

Запуск вместе с Windows хранится не в `settings.json`, а в реестре
(раздел Run текущего пользователя): переключатель в настройках окна или
вкладка «Автозагрузка» диспетчера задач.

`settings.json` хранит ключи Twitch, `downloads.json` — очередь загрузок;
в репозиторий они не попадают.

### Ключи Twitch

`twitch_client_id` и `twitch_client_secret` — ключи «приложения» Twitch,
а не пароль от аккаунта. Они по желанию: с ними программа узнаёт, что канал
в эфире, через официальный API Twitch раз в 15 секунд, без них — через
streamlink раз в 30 секунд. Аватарки каналов видны и без ключей.

Как получить:

1. Войти на [dev.twitch.tv/console/apps](https://dev.twitch.tv/console/apps)
   (на аккаунте Twitch должна быть включена двухфакторная защита).
2. Register Your Application: Name — любое свободное имя, OAuth Redirect
   URLs — `http://localhost`, Category — Application Integration,
   Client Type — Confidential. Create.
3. Manage у созданного приложения: Client ID — в настройки программы,
   затем New Secret — это Client Secret.

## Тесты

```
python -m unittest discover
```

Тесты записи, загрузок и конвертации запускают настоящие streamlink, yt-dlp
и ffmpeg на локальном HTTP-сервере, сеть им не нужна. Без этих программ
соответствующие тесты пропускаются.
